На веб-сайтах, использующих процесс входа по паролю, пользователи либо регистрируют учётную запись самостоятельно, либо она назначается им администратором. Эта учётная запись связана с уникальным именем пользователя и секретным паролем, который пользователь вводит в форму входа.

В этом сценарии тот факт, что пользователь знает секретный пароль, считается достаточным доказательством его личности. Это означает, что безопасность веб-сайта оказывается под угрозой, если злоумышленник способен получить или угадать учётные данные для входа другого пользователя.

## Атаки методом перебора

Атака методом перебора — это когда злоумышленник использует систему проб и ошибок для угадывания действительных учётных данных пользователя. Такие атаки обычно автоматизируются с использованием словарей имён пользователей и паролей.

### Перебор имён пользователей
Имена пользователей легко угадать, если они соответствуют распознаваемому шаблону, например адресу электронной почты. Однако даже при отсутствии очевидного шаблона иногда даже учётные записи с высокими привилегиями создаются с использованием предсказуемых имён пользователей, таких как admin или administrator.

### Перебор паролей
Пароли аналогичным образом можно перебирать, причём сложность варьируется в зависимости от надёжности пароля. Многие веб-сайты применяют ту или иную политику паролей, которая заставляет пользователей создавать пароли трудные для взлома.

Даже так зачастую пароли уязвимы по человеческому фактору:
- Вместо создания надёжного пароля из случайных символов пользователи часто берут пароль, который могут запомнить, и адоптирует его в рамки политики паролей. Например, вместо `mypassword` ставить `Mypassword1!` или `Myp4$$w0rd`;
- Когда политика требует от пользователей регулярно менять пароли, пользователи просто вносят незначительные, предсказуемые изменения в свой предпочитаемый пароль. Например, `Mypassword1!` становится `Mypassword1?` или `Mypassword2!`;

Это знание вероятных учётных данных и предсказуемых шаблонов означает, что атаки методом перебора часто могут быть гораздо более изощрёнными и, следовательно, эффективными, чем просто перебор всех возможных комбинаций символов.

### Перечисление имён пользователей
Перечисление имён пользователей — это когда злоумышленник способен наблюдать изменения в поведении веб-сайта, чтобы определить, является ли данное имя пользователя действительным.

 Это значительно сокращает время и усилия, необходимые для перебора учётных данных для входа, поскольку злоумышленник может быстро составить короткий список действительных имён пользователей.

При переборе страницы входа обращайте внимание на различия в:
1. **Кодах состояния:** одинаковый код для большинства попыток — норма. Другой код — вероятно, имя пользователя верное;
2. **Сообщениях об ошибках:** разные тексты для «неверное имя + пароль» и «неверный только пароль» выдают валидные имена. Даже один символ делает сообщения различными;
3. **Времени ответа:** отклонения от обычного времени указывают на иную логику за кулисами. Например, сайт проверяет пароль только при верном имени пользователя — это замедляет ответ. Длинный пароль делает задержку заметнее.
