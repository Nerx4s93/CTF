Например приложение, которое отображает изображения. Оно может загружать изображение с помощью следующего HTML-кода:
```html
<img src="/loadImage?filename=218.png">
```

URL-адрес `loadImage` принимает параметр `filename` и возвращает содержимое указанного файла. Файлы изображений хранятся на диске в каталоге `/var/www/images/`, чтобы вернуть изображение, приложение добавляет запрошенное имя файла к этому базовому каталогу и читает содержимого файла:
```
/var/www/images/218.png
```

Это приложение не реализует никаких защитных мер против атак типа «обход пути». В результате злоумышленник может запросить следующий URL-адрес, чтобы получить файл `/etc/passwd` из файловой системы сервера:
```
https://insecure-website.com/loadImage?filename=../../../etc/passwd
```

Это заставляет приложение читать по следующему пути:
```
/var/www/images/../../../etc/passwd
```

В Windows как `../`, так и `..\` являются допустимыми последовательностями обхода каталога. Ниже приведён пример эквивалентной атаки на сервер под управлением Windows:
```
https://insecure-website.com/loadImage?filename=..\..\..\windows\win.ini
```
