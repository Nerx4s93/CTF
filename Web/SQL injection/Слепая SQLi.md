Слепая SQL-инъекция возникает, когда приложение уязвимо к SQLi, но его HTTP-ответы не содержат результатов SQL-запроса или сведений об ошибках базы данных.

Многие методы, такие как UNION-атаки, неэффективны при уязвимостях слепой SQLi. Это связано с тем, что они полагаются на возможность видеть результаты внедрённого запроса в ответах приложения. Тем не менее, слепую SQL-инъекцию всё ещё можно использовать для доступа к несанкционированным данным, но для этого необходимо применять другие методы.

## Эксплуатация слепой SQL-инъекции путём вызова условных ответов

Например, приложение, которое использует отслеживающие cookie-файлы для сбора аналитики об использовании. Запросы к приложению содержат заголовок cookie примерно такого вида:
```
Cookie: TrackingId=u5YD3PapBcR4lN3e7Tj4
```

Когда обрабатывается запрос, содержащий cookie `TrackingId`, приложение использует SQL-запрос, чтобы определить, является ли этот пользователь известным:
```sql
SELECT TrackingId FROM TrackedUsers WHERE TrackingId = 'u5YD3PapBcR4lN3e7Tj4'
```

Этот запрос уязвим к SQLi, но результаты запроса не возвращаются пользователю. Однако приложение ведёт себя по-разному в зависимости от того, возвращает ли запрос какие-либо данные. Если отправить распознанный `TrackingId`, запрос вернёт данные.

### Идея эксплуатации

Допустим, поочерёдно отправляются два запроса, содержащие следующие значения cookie `TrackingId`:
```
…xyz' AND '1'='1
…xyz' AND '1'='2
```

Первое из этих значений заставляет запрос вернуть результаты, потому что внедрённое условие `AND '1'='1` истинно, а второе значение заставляет запрос не возвращать никаких результатов, потому что внедрённое условие ложно, что позволяет определить ответ на внедрённое условие и извлекать данные по частям.

Например, существует таблица с именем `Users` со столбцами `Username` и `Password`, а также пользователь с именем `Administrator`. Можете определить пароль этого пользователя, отправляя серию входных данных для проверки пароля по одному символу за раз.

### Пример

Используя функцию `SUBSTRING` (`SUBSTR` на некоторых других баз данных) можно по частям угадывать пароль:
```
xyz' AND SUBSTRING((SELECT Password FROM Users WHERE Username = 'Administrator'), 1, 1) > 'm
```

Продолжая посимвольное сравнение можно определить полный пароль пользователя `Administrator`.
