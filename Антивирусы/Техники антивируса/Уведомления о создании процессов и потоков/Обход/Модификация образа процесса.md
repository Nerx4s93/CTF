Весь рабочий процесс создания процесса, где шаг уведомления выделен жирным шрифтом:
1. Проверить параметры, переданные в API создания процесса.
2. Открыть хэндл целевого образа.
3. Создать объект секции (section object) из целевого образа.
4. Создать и инициализировать объект процесса.
5. Выделить PEB.
6. Создать и инициализировать объект потока.
7. **Отправить уведомление о создании процесса зарегистрированным callback-процедурам.**
8. Выполнить специфичные для подсистемы Windows операции для завершения инициализации.
9. Начать выполнение главного потока.
10. Финализировать инициализацию процесса.
11. Начать выполнение с точки входа образа (entry point).
12. Вернуть управление вызывающей стороне API создания процесса.

## Hollowing

Hollowing — один из старейших способов использования модификации секций.

Поток выполнения Process Hollowing:
![](../../../../z.%20Images/{5C011B7E-33E5-4D83-AF9A-B50E3D8ABEAF}.png)

Используя эту технику, атакующий создает процесс в приостановленном состоянии, затем отменяет отображение (unmaps) его образа после определения его базового адреса в PEB. Как только отмена отображения завершена, атакующий отображает новый образ (например, shellcode runner атакующего) в процесс и выравнивает его секцию.

## Doppelgänging

Техника, process doppelgänging, опирается на две функции Windows: Transactional NTFS (TxF) и устаревший API создания процессов ntdll!NtCreateProcessEx().

TxF — это устаревший ныне метод выполнения действий с файловой системой в виде единой атомарной операции. Он позволяет коду легко откатывать изменения файлов (например, во время обновления или в случае ошибки) и имеет собственную группу поддерживающих API

Устаревший API создания процессов выполнял создание процессов до выпуска Windows 10, где был представлен более надежный ntdll!NtCreateUserProcess(). Чтобы использовать устаревшую функцию создания процессов, разработчик должен воссоздать эти недостающие шаги в своем собственном коде, чтобы гарантировать запуск процесса.

## Herpaderping

Использует многие из тех же трюков, что и process doppelgänging, а именно использование устаревшего API создания процессов для создания процесса из объекта секции. Его основная цель — обойти обнаружение содержимого сброшенного на диск исполняемого файла.

## Ghosting

Process ghosting опирается на тот факт, что Windows предотвращает удаление файлов только после того, как они отображены в секцию образа, и не проверяет, существует ли на самом деле связанная секция во время процесса удаления. Если пользователь попытается открыть отображенный исполняемый файл для изменения или удаления, Windows вернет ошибку. Если разработчик помечает файл для удаления, а затем создает секцию образа из исполняемого файла, файл будет удален при закрытии хэндла файла, но объект секции сохранится.

## Детекты

Хотя модификация образа процесса имеет казалось бы бесконечное количество вариаций, их всех возможно обнаружить, используя одни и те же базовые методы, благодаря зависимости техники от двух вещей:
- создания секции образа, отличающейся от сообщаемого исполняемого файла.
- использования устаревшего API создания процессов для создания нового, не минимального процесса из секции образа.
