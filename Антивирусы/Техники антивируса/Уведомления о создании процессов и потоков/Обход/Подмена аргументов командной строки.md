Некоторые стратегии обнаружения даже полностью построены вокруг конкретных аргументов командной строки, связанных с известным атакующим инструментом или вредоносным ПО.

EDR могут найти аргументы в элементе CommandLine структуры, переданной в процедуру обратного вызова создания процесса. При создании процесса его аргументы командной строки хранятся в поле ProcessParameters его PEB. Это поле содержит указатель на структуру RTL_USER_PROCESS_PARAMETERS, которая содержит, UNICODE_STRING с параметрами, переданными процессу при вызове.

Поскольку PEB находится в пространстве памяти режима пользователя (user-mode) процесса, а не в ядре, процесс может изменять атрибуты своего собственного PEB.

``` C
void main()
{
    STARTUPINFOW si;
    ZeroMemory(&si, sizeof(si));
    si.cb = sizeof(si);
    PROCESS_INFORMATION pi;
    ZeroMemory(&pi, sizeof(pi));
    if (!CreateProcessW(
        L"C:\\Windows\\System32\\cmd.exe",
        L"These are my sensitive arguments",
        NULL, NULL, FALSE, 0,
        NULL, NULL, &si, &pi))
    {
    }
        WaitForSingleObject(pi.hProcess, INFINITE);
    return;
}
```

Эта базовая реализация порождает дочерний процесс cmd.exe с аргументами "These are my sensitive arguments". При выполнении процесса любой стандартный инструмент мониторинга процессов должен увидеть этот дочерний процесс и его неизмененные аргументы, прочитав их из PEB:

Обход: сначала создаётся дочерний процесс в приостановленном состоянии, используя вредоносные аргументы, затем используется, ntdll!NtQueryInformationProcess(), чтобы получить адрес PEB дочернего процесса, и копируется его с помощью вызова kernel32!ReadProcessMemory(). После извлекается его поле ProcessParameters и перезаписываете UNICODE_STRING, представленный элементом CommandLine, на который указывает ProcessParameters, с поддельными (spoofed) аргументами. Наконец, возобновление дочернего процесса.
