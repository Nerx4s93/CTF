
Большинство EDR полагаются на функциональность, предоставляемую их драйвером режима ядра, который является компонентом сенсора, работающим в привилегированном слое операционной системы ниже пользовательского режима. Эти драйверы дают разработчикам возможность использовать функции, доступные только внутри ядра, обеспечивая EDR многими превентивными возможностями и телеметрией.

Процедура обратного вызова - это внутренние подпрограммы, которые предпринимают действия при возникновении определенного системного события.

## Суть работы

Драйвер регистрирует процедуры обратного вызова, которые по сути просто говорят: «Дай мне знать, если в системе произойдет событие этого типа, чтобы я мог что-то сделать». В результате этих уведомлений драйвер может предпринять необходимые действия.

Процедуры обратного вызова могут быть либо до выполнения операции, происходящими до завершения события, либо после выполнения операции, происходящими после нее. Callback-процедуры pre-operation более распространены в EDR, так как они дают драйверу возможность вмешаться в событие или предотвратить его завершение.

## Уведомления о процессах

Пример регистрации функции:
``` C
NTSTATUS DriverEntry(PDRIVER_OBJECT pDriverObj, PUNICODE_STRING pRegPath)
{
    NTSTATUS status = STATUS_SUCCESS;
    --snip-
    status = PsSetCreateProcessNotifyRoutineEx2(
        PsCreateProcessNotifySubsystems,
        (PVOID)ProcessNotifyCallbackRoutine,
        FALSE
    );
    --snip-
}
void ProcessNotifyCallbackRoutine(
    PEPROCESS pProcess,
    HANDLE hPid,
    PPS_CREATE_NOTIFY_INFO pInfo)
{
    if (pInfo)
    {
        --snip-
    }
}
```

При создании нового процесса указатель на структуру PS_CREATE_NOTIFY_INFO передается в callback:
``` C
typedef struct _PS_CREATE_NOTIFY_INFO {
    SIZE_T Size;
    union {
        ULONG Flags;
        struct {
            ULONG FileOpenNameAvailable: 1;
            ULONG IsSubsystemProcess: 1;
            ULONG Reserved: 30;
        };
    };
    HANDLE ParentProcessId;
    CLIENT_ID CreatingThreadId;
    struct _FILE_OBJECT *FileObject;
    PCUNICODE_STRING ImageFileName;
    PCUNICODE_STRING CommandLine;
    NTSTATUS CreationStatus;
} PS_CREATE_NOTIFY_INFO, *PPS_CREATE_NOTIFY_INFO;
```

Эта структура содержит значительный объем ценных данных, относящихся к событиям создания процессов в системе. Эти данные включают:
- ParentProcessId: Родительский процесс вновь созданного процесса. Это не обязательно тот процесс, который действительно создал новый процесс.
- CreatingThreadId: Хэндлы уникального потока и процесса, ответственного за создание нового процесса.
- FileObject: Указатель на файловый объект исполняемого файла процесса (образ на диске).
- ImageFileName: Указатель на строку, содержащую путь к исполняемому файлу вновь созданного процесса.
- CommandLine: Аргументы командной строки, переданные создающему процессу.
- FileOpenNameAvailable: Значение, которое определяет, соответствует ли элемент
- ImageFileName имени файла, использованному для открытия исполняемого файла нового процесса.

## Уведомления о потоках

При создании или завершении потока callback-процедура получает три фрагмента данных: ID процесса, которому принадлежит поток, уникальный ID потока и логическое значение, указывающее, создается ли поток.

``` C
NTSTATUS DriverEntry(PDRIVER_OBJECT pDriverObj, PUNICODE_STRING pRegPath)
{
    NTSTATUS status = STATUS_SUCCESS;
    --snip-
    status = PsSetCreateThreadNotifyRoutine(ThreadNotifyCallbackRoutine);
    --snip-
}
void ThreadNotifyCallbackRoutine(
    HANDLE hProcess,
    HANDLE hThread,
    BOOLEAN bCreate)
{
    if (bCreate)
    {
        --snip-
    }
}
```

Как и при создании процесса, EDR может получать уведомления о создании или завершении потока через свой драйвер, регистрируя callback-процедуру уведомления о потоках с помощью nt!PsSetCreateThreadNotifyRoutine() или расширенной nt!PsSetCreateThreadNotifyRoutineEx(), которая добавляет возможность определять тип уведомления.

## Обнаружение создания удаленных потоков

Создание удаленного потока происходит, когда один процесс создает поток внутри другого процесса.

``` C
void ThreadNotifyCallbackRoutine(
    HANDLE hProcess,
    HANDLE hThread,
    BOOLEAN bCreate)
{
    if (bCreate)
    {
        if (PsGetCurrentProcessId() != hProcess) // 1
        {
            --snip-
        }
    }
}
```

Некоторые внутренние компоненты операционной системы также выполняют легитимное создание удаленных потоков. Примером этого является отчетность об ошибках Windows (werfault.exe). Когда в системе происходит ошибка, операционная система порождает werfault.exe как дочерний процесс от svchost.exe (в частности, службы WerSvc), а затем внедряет его в сбойный процесс.

Таким образом, тот факт, что поток был создан удаленно, не делает его автоматически вредоносным. Чтобы определить это, EDR должен собрать дополнительную информацию.
